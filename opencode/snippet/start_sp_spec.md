---

use superpowers/brainstorming

작업 요청

$ARGUMENTS

진행 원칙

1. 먼저 저장소 구조, 관련 코드, 기존 문서와 최근 변경 사항을 확인하세요.
2. 코드 탐색 범위가 넓다면 직접 모든 파일을 읽지 말고 @sp-explorer를 사용하세요.
3. 요구사항, 목적, 제약 조건, 성공 기준을 파악하세요.
4. 불명확한 내용은 한 번에 하나씩 질문하세요.
5. 구현 방법을 바로 결정하지 말고 2~3개의 접근 방법과 장단점을 제시하세요.
6. 사용자의 선택을 받은 뒤 설계를 구체화하세요.
7. 사용자의 승인 전에는 구현하거나 production code를 수정하지 마세요.
8. 설계에는 다음 내용을 포함하세요.
    * 목표와 배경
    * 요구사항
    * 비기능 요구사항
    * 아키텍처와 주요 컴포넌트
    * 데이터 흐름
    * 오류 처리
    * 테스트 전략
    * 비대상 범위
    * 확정된 의사결정
9. 중요하거나 위험한 설계는 @sp-spec-review에 독립 검토를 요청하세요.
10. 승인된 설계를 다음 경로에 저장하세요.

docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md

11. 문서 저장 후 다음 항목을 자체 점검하세요.

* TODO, TBD 또는 placeholder가 남아 있지 않은가
* 요구사항과 설계가 서로 모순되지 않는가
* 여러 의미로 해석될 표현이 없는가
* 하나의 구현 계획으로 처리하기에 범위가 너무 크지 않은가

12. 설계 문서를 작성한 뒤 사용자에게 검토를 요청하고, 승인 전에는 plan 단계로 넘어가지 마세요.
